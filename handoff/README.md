# Shooter aim — handoff package

Give it the horizontal distance to the HUB; it returns a **launch angle** and a **flywheel
surface speed**. At the field you tune **one number**, `kSpeed`.

Everything here is generated by the AlphaSim repository
(https://github.com/Alphabots-8810/AlphaSim). Do not edit the coefficients by hand; regenerate.

## Files

| File | What it is |
|---|---|
| `ShooterAim.java` | The function (Java 17, WPILib). Drop it into robot code. |
| `shooter_aim.py` | The same function in Python (RobotPy, or for checking offline). |
| `lookup_polynomial.json` | The same coefficients, machine-readable, with the solver's table and checks. |
| `shooter_sim.html` | The simulator. Open it in a browser; it works offline. |
| `research_report.html` | The report: model, error budget, results, what to measure. Works offline. |

## Quick start

```java
double d = distanceToHubMeters();                  // from where the ball leaves the shooter
ShooterAim.Aim a = ShooterAim.aimFor(d);
setHoodAngle(a.hoodAngleDeg());                    // degrees above horizontal
setFlywheelSurfaceSpeed(a.flywheelSpeedMps());     // m/s at the wheel rim
```

```python
from shooter_aim import aim
hood_deg, flywheel_mps = aim(d)
```

Valid from **1.5 to 5.0 m**. Outside that the input is clamped to the nearest end, not
extrapolated.

## Four things to get right

**1. The angle is the ball's launch angle above horizontal.** 90° would be straight up. It is not
a hood encoder reading. Work out the offset between your hood's zero and horizontal, and check it
with one measured shot before trusting the curve.

**2. The speed is the flywheel's surface (rim) speed in m/s,** so it does not depend on wheel size.
For your wheel of diameter `D` metres:

```
rpm = v / (Math.PI * D) * 60
```

**3. `kSpeed` depends on how your shooter grips the ball.** The formulas assume the ball leaves at
0.82 of the rim speed, which is about right for powered rollers on both sides of the ball.

| Shooter | Where `kSpeed` should start |
|---|---|
| Powered rollers on both sides, same surface speed | about 1.0 |
| Flywheel on one side, **fixed** hood plate on the other | about 2.0 — the ball rolls on the plate, so its centre moves at half the rim speed |

Then tune it: stand 3 m from the hub and fire. Balls landing **short → raise** `kSpeed`; landing
**long → lower** it. One number absorbs slip, ball compression, battery sag and errors in the air
model.

**4. The exit height is baked in.** These coefficients are for a ball leaving **0.50 m** above the
carpet. Changing `SHOOTER_HEIGHT_M` in the file does nothing. If your robot differs by more than a
couple of centimetres, set `shooter.exit_height_m` in the repository's `config/robot.yaml` and
run `python scripts/build_site.py` to get a new package.

## The optional second knob

`kSpeedSlope` lets the gain change in a straight line with distance:

```
gain = kSpeed + kSpeedSlope × (d − 3.0)
```

Leave it at **0** unless shots near 3 m are centred but far or close ones are not. If they are
not: find the gain that centres a shot at about 2 m and the gain that centres one at about
4.5 m, then set `kSpeedSlope` = (gain at 4.5 m − gain at 2 m) ÷ 2.5 and
`kSpeed` = (gain at 2 m) + `kSpeedSlope`. In simulation this takes the error left after
calibration from several centimetres to under two, even when the drag and spin assumptions are
well off (report, section 7).

## Time of flight

`timeOfFlightS(d)` returns how long the ball is in the air. It is there for shooting while
moving: aim at where the hub will be, relative to the robot, that many seconds from now. This has
not been tested on a robot, and it ignores how the robot's own speed changes the ball's drag.
Treat it as a starting point.

## What changed from the previous package

The coefficients now come from solver version 5 (see the report). Against the version 3.1 curve
shipped before:

- Launch angle differs by at most 1.3° (at 1.5 m) and by less than 0.6° beyond 3 m.
- Flywheel speed differs by at most 1.5 %.
- A robot already tuned on the old curve should not need retuning; re-centre with `kSpeed` if you
  switch.
- `aimFor`, `hoodAngleDeg`, `flywheelSpeedMps` and `kSpeed` keep their names and meaning.
  `kSpeedSlope`, `D_REF` and `timeOfFlightS` are new.
- The doc comment on the angle used to say "90° = straight down". That was wrong; it is degrees
  above horizontal, as it always behaved.

## How sure are these numbers

With the ball-to-ball scatter assumed in the report, about 99.7 % of balls score from 3 m and
96 % from 5 m. Those scatter values are estimates that nobody has measured on the robot yet.
The simulator's sliders let you put in what you measure and see what changes.
